풋살 대회 기록 웹 계획서
2026년 10월 6일 · @박진
개요
풋살 대회 당일, 운영진이 경기 결과를 실시간으로 입력하면 조별 순위와 결승·3·4위전 대진이 자동으로 계산되고, 누구나 결과 페이지에서 볼 수 있는 웹을 만든다. 중등부와 고등부는 완전히 따로 운영하고, 대회는 하루(3개 구장 동시 진행)에 끝난다.

사용자 시나리오
운영진이 3개 구장에서 동시에 심판을 보며 기록하고, 참가 팀은 월드컵 조별리그처럼 결과와 대진을 확인한다.
운영진(심판·주최)
1. 대회 전: 팀·선수 명단과 시간표가 미리 들어가 있다.
2. 추첨 후: 슬롯에 팀을 배정한다.
3. 경기 중: 각 구장 담당자가 폰으로 자기 구장의 현재 경기를 열고, 골이 나면 득점 선수를, 카드가 나오면 선수와 경고/퇴장을 바로 입력한다.
4. 경기 후: 종료 처리하면 순위표가 갱신된다.
5. 조별 리그 후: 결승·3·4위전 대진을 확정하고, 같은 방식으로 기록한다.
참가 팀·관중
1. 공개 주소로 들어와 자기 부문 탭을 고른다.
2. 조별 순위표와 경기 결과(스코어, 득점자, 카드)를 월드컵 조별리그 화면처럼 본다.
3. 조별 리그가 끝나면 결승·3·4위전 대진과 최종 1·2·3위를 확인한다.
대회 규칙
• 고등부 6팀: 3팀씩 2개 조(A조: 1~3번, B조: 4~6번) 풀리그 후, 조 1위끼리 결승, 조 2위끼리 3·4위전.
• 중등부는 팀 수에 따라 구성이 다르며, supabase/middle/{4,5,6}.sql 중 하나를 실행해 바꾼다(코드 수정 없음). 현재 4팀.
  - 4팀: 리그 1개(1~4번) 풀리그 6경기. 토너먼트 없이 리그 순위가 최종 순위.
  - 5팀: A조 2팀(1·2번), B조 3팀(3~5번) 후 결승(A1 vs B1)·3·4위전(A2 vs B2).
  - 6팀: 3팀씩 2개 조 후 결승·3·4위전(고등부와 같음).
• 팀 배정: 팀과 번호(조)는 대회 당일 추첨으로 정한다.
• 팀은 학교가 섞인 클럽 팀이므로 화면에는 학교가 아닌 팀 이름을 표시한다.
• 경기 시간: 모든 경기 15분.
• 승점: 승 3, 무 1, 패 0. 조별 리그는 무승부를 허용한다.
• 퇴장: 한 경기에서 경고 2장을 받거나, 다이렉트 퇴장을 받으면 퇴장이다.
• 매너점수: 경고 −1, 퇴장 −3. 0에서 시작해 감점하며 높을수록 좋다. 한 선수의 한 경기 감점은 퇴장이 있으면 −3(경고 감점은 중복하지 않음), 없으면 경고 수 × −1.
• 순위 기준(조 안에서만 비교): 매너점수 → 승점 → 득실차 → 다득점 → 승자승. 이 순서는 대회 요강대로 매너점수가 1순위다.
• 출장정지: 퇴장(경고 2장 포함) 받은 선수는 그 팀의 다음 경기에 출장할 수 없다. 경기 간 경고 누적으로는 출장정지되지 않는다.
• 토너먼트 동점 처리: 연장 없이 바로 승부차기.
• 이벤트 경기(12:00): 기록하지 않는다.
시간표
포스터(제주 with us, 3구장) 기준. 경기는 15분, 경기 사이 15분은 팀 교체·휴식이다. 경기는 팀이 아닌 번호로 잡혀 있으며, supabase/seed.sql·middle/4.sql과 같다.
포스터의 중등부는 6팀(3팀씩 2개 조) 기준이라, 실제 4팀 리그는 포스터의 중등부 칸 6개(10:15 3구장, 10:45 2·3구장, 11:15 3구장, 11:45 2·3구장)에 6경기를 넣었다. 6팀이 되면 middle/6.sql이 포스터와 같다.

핵심 설계: 번호 슬롯과 진출 규칙
팀 수와 조 편성이 바뀌어도 코드를 고치지 않도록, 경기는 "번호(슬롯)"끼리, 토너먼트는 "진출 규칙"으로 저장한다.
번호 슬롯
• 경기는 처음부터 고등1 vs 고등2처럼 슬롯끼리 잡아 seed한다.
• 당일 추첨 후 운영진이 슬롯에 팀을 배정한다(예: 중등3 = 쪼꼬미).
• 화면은 배정 전에는 번호, 배정 후에는 팀 이름을 보여준다.
• 중등부 팀 수가 바뀌면 슬롯과 경기 목록 데이터만 바꾼다.
진출 규칙
• 결승과 3·4위전은 팀 대신 출처를 저장한다: A:1(A조 1위), B:2(B조 2위) 같은 형식.
• 해당 조의 경기가 모두 종료되면 순위를 계산해 실제 팀으로 채운다.
• 조가 하나(단일 리그)면 화면에 'A조' 대신 '리그'로 표시한다. 토너먼트 경기가 없는 부문은 리그가 끝나고 1~3위가 동률이 아니면 리그 순위를 최종 순위로 표시한다.
• 계산이 애매한 경우(모든 기준 완전 동률 등)를 위해 운영진이 팀을 직접 지정하는 수동 오버라이드를 둔다.
데이터 모델
Supabase 테이블 6개로 구성하고, 순위표는 저장하지 않고 matches·goals·cards에서 매번 계산한다. 그래야 결과를 수정해도 순위가 어긋나지 않는다.

매너점수·출장정지 계산 근거
• 스코어는 goals를 팀별로 세어 계산한다. 그래서 스코어와 득점자 기록이 어긋날 수 없다.
• 득점·카드의 minute은 입력 시점에 started_at 기준 경과 분으로 자동 채우고, 운영진이 수정할 수 있다.
• 같은 선수에게 한 경기에서 두 번째 경고를 입력하면 자동으로 second_yellow(경고누적 퇴장)로 저장한다.
• 토너먼트 경기가 동점으로 끝나면 바로 승부차기 스코어(home_pk, away_pk)를 입력한다. 연장 컬럼은 두지 않는다.
순위 계산 로직
순위 계산은 DB와 분리된 순수 함수(lib/standings.ts)로 만들고, UI보다 먼저 테스트를 작성한다.
1. 입력: 한 조의 슬롯 목록, status = finished인 조별 경기, 해당 경기의 득점·카드 목록(스코어는 득점 기록에서 계산).
2. 팀별로 경기수, 승·무·패, 득점, 실점, 득실차, 승점, 경고 수, 퇴장 수, 매너점수를 집계한다. 매너점수는 선수·경기 단위로 퇴장(`second_yellow` 또는 `red`)이 있으면 −3, 없으면 경고 수 × −1을 팀별로 합산한다.
3. 정렬 기준 배열 RANKING_ORDER = ['manner', 'points', 'goalDiff', 'goalsFor', 'headToHead']를 설정값으로 두고 순서대로 비교한다.
4. 승자승은 동률인 팀끼리의 경기만으로 승점을 다시 계산해 비교한다(3팀 동률도 처리).
5. 모든 기준이 같으면 동률로 표시하고, 운영진 수동 지정을 요구한다.
진출 규칙 해석: A:1은 A조의 모든 경기가 finished일 때만 팀으로 바뀌고, 그 전에는 "A조 1위"로 표시한다. manual 값이 있으면 그것을 우선한다.
출장정지: 선수에게 second_yellow 또는 red 카드가 있으면, 그 팀의 다음 경기(start_time 기준)에서 출장정지로 표시한다.
테스트 케이스(최소): 매너점수가 승점을 뒤집는 경우, 득실차 동률 후 다득점, 2팀 승자승, 3팀 완전 동률, 2팀짜리 조, 경기 일부만 종료된 상태, 경고 2장 퇴장의 매너점수(−3)와 출장정지, 자책골이 득점 순위에서 빠지는지.

보안 방침
로그인 없이 비밀 주소로 운영진 페이지를 보호하기로 했다(유출 위험은 감수). 대신 DB를 브라우저에서 직접 수정할 수 없게 막는다.
• 비밀 경로는 환경변수(ADMIN_PATH)로 관리하고 코드·저장소에 하드코딩하지 않는다.
• Supabase RLS: anon 키는 모든 테이블 읽기만 허용한다.
• 모든 쓰기는 Next.js 서버 액션에서 service role 키(SUPABASE_SERVICE_ROLE_KEY, 서버 전용)로만 수행한다.
• 운영진 페이지에 noindex를 넣어 검색 노출을 막는다.
구현 순서
각 단계는 끝날 때마다 동작을 확인하고 커밋한 뒤 다음 단계로 넘어간다.
1. DB 준비: Supabase 테이블 6개, RLS(읽기 전용), 시간표 seed 스크립트, 참가 신청 시트(xlsx) → teams·players import 스크립트.
2. 순위 로직: lib/standings.ts와 진출 규칙 해석, 출장정지 판정. 테스트 케이스 먼저 통과시킨다.
3. 공개 페이지: 부문 탭, 월드컵식 조별 순위표·경기 카드, 토너먼트 카드, 득점 순위, 경기 상세.
4. 운영진 페이지: 추첨 배정 → 경기 입력 → 토너먼트 확정, 서버 액션으로 쓰기.
5. 실시간·배포: Supabase Realtime 구독, Vercel 배포, 환경변수 설정.
6. 리허설: 가짜 팀·결과로 대회 하루(추첨부터 시상까지)를 처음부터 끝까지 돌려보고, 폰으로 입력 속도를 확인한다.
